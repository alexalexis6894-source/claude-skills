# Apify: что реально приходит и сколько стоит

> Протокол оптимизации, реестр цен и журнал тестов живут в `actor-playbook.md`.
> Этот файл про поля, границы поиска и грабли прогона.

Проверено на прогонах сентября 2026, акторы `clockworks~tiktok-scraper` и `apify~instagram-scraper`.

## Цены и модель оплаты

| Что | Цена за запись | Откуда число |
|---|---|---|
| TikTok поиск | около $0,0023 | $4,64 за 2059 записей, сбор 22.09.2026 |
| TikTok поиск, прежняя оценка | около $0,0025 | $2,74 за 300 записей |
| Instagram посты | около $0,0035 | $0,63 за 180 записей |
| ИИ-описание видео | $0,00222 за секунду видео | проба на трёх роликах |

Оплата PAY_PER_EVENT, списывается по факту. Смету считать до запуска (число запросов × цена за 100 записей, `maxTotalChargeUsd` в задании), остаток смотреть
через `/v2/users/me/usage/monthly`. Один аккаунт могут делить несколько сессий: баланс проверять перед каждым сбором.

**ИИ-описания не покупать.** Топ-100 роликов обойдётся примерно в $10 и даст то же, что бесплатно лежит в подписи
и хэштегах. Держать `aiVideoDescription: false`, `downloadSubtitlesOptions: NEVER_DOWNLOAD_SUBTITLES`.

## Какие поля приходят бесплатно

TikTok: `id`, `text` (подпись), `hashtags[].name`, `playCount`, `diggCount`, `commentCount`, `collectCount`,
`shareCount`, `videoMeta.duration`, `createTimeISO`, `authorMeta` (имя, ник, подписчики, описание профиля),
`webVideoUrl`, `textLanguage`, `isAd`, `isSponsored`.

Instagram: `id`/`shortCode`, `caption`, `hashtags`, `videoPlayCount`, `likesCount`, `commentsCount`,
`videoDuration`, `timestamp`, `ownerUsername`, `url`. Просмотры приходят числом только у видео.

Чего нет ни там, ни там: что именно происходит в кадре, звук, удержание, досмотры, источник трафика.

## Границы поиска

- **Поправка от 16.09.2026: фильтры по дате и сортировка в поиске ЕСТЬ.** У `clockworks~tiktok-scraper`
  в схеме есть `videoSearchDateFilter` со значениями `ALL_TIME`, `PAST_24_HOURS`, `PAST_WEEK`,
  `PAST_MONTH`, `LAST_3_MONTHS`, `LAST_6_MONTHS` и `videoSearchSorting` со значениями `MOST_RELEVANT`,
  `MOST_LIKED`, `LATEST`. Оба работают только при `searchSection: "/video"` и оба платные надстройки
  (события `filter-applied` и `mobile-filter-sorting-applied`). Для профилей отдельно есть
  `oldestPostDateUnified` и `newestPostDate`, они работают только с `profileSorting` latest или oldest.
  Старое утверждение «фильтра нет» относилось к прогонам до августа 2026.
- Порог «залетевшего» по просмотрам по-прежнему ставится после сбора: фильтра по `playCount` нет.
- Поиск не перечисляет базу площадки, он отдаёт релевантное. Полного списка «всё по теме за 5 лет» получить нельзя.
- **Поправка от 22.09.2026 по парфюмерной нише: рост доли по глубине не универсален.** На выборке
  1870 роликов доля залетевших по позициям вышла ровной: 22% на 1-25, 18% на 26-50, 14% на 51-75,
  19% на 76-100. Вывод про хвост остаётся практическим (глубину резать невыгодно), но как закон
  его переносить на новую нишу нельзя, надо считать по своим данным.
- Доля залетевших РАСТЁТ с глубиной выдачи, а не падает: на позициях 1-25 это 23%, на 76-100 уже 35%
  (3154 записи, сбор сентября 2026). Причина: наверху выдачи свежие ролики, они ещё не набрали просмотры,
  а глубже лежат старые с накопленными. Значит резать `resultsPerPage` ради экономии невыгодно:
  дешёвая часть выборки как раз в хвосте.
  **Это верно для сортировки по умолчанию.** При `videoSearchSorting: MOST_LIKED` порядок обратный:
  залетевшие идут сверху, и глубина хвоста перестаёт быть источником находок. Две настройки
  взаимоисключающие, выбирать одну.
- Обратная сторона: по первым двадцати записям нельзя судить о запросе. Ранговая корреляция качества
  запроса по топ-20 с качеством по всей сотне всего 0,66: «interior designer reacts» дал 0% залетевших
  в топ-20 и 25% на всей выдаче. Дешёвая разведка по 20 записей отбросит хорошие запросы.
- Выдача смещена к свежему: в сборе сентября 2026 на 2026 год пришлось 59% записей.
- Один ролик приходит по нескольким запросам: дедупликация по `id` обязательна, иначе популярное считается дважды.

## Грабли прогона

| Симптом | Причина | Что делать |
|---|---|---|
| `CERTIFICATE_VERIFY_FAILED` | системный python 3.7 без сертификатов | поставить актуальный python 3.10+ и запускать им |
| Сбор обрывается на середине | `nohup ... &` умирает вместе с задачей Bash | запускать фоновой задачей инструмента |
| Повторный сбор дорожает | перезапуск всех запросов | в `jobs-*.json` оставить только пропущенные запросы и запустить `apify_jobs.py` ещё раз (готовые прогоны он пропускает сам) |
| Прогон висит в `RUNNING` больше 30 минут | актор ждёт прокси | смотреть `console_url` из `logs/*.run.json` |
| `ConnectionResetError` на выгрузке датасета | Apify рвёт соединение, прогон при этом уже оплачен | `apify_jobs.py` повторяет выгрузку; оплаченный прогон не перезапускать, а забрать датасет по id прогона |
| Прогон SUCCEEDED, а в файле одна запись с `id: null` | актор не нашёл ничего по запросу и вернул пустышку | счёт около $0,001, файл удалить и запрос не повторять: формулировка мёртвая |

## Где реально экономить

Разбор фактического счёта $9,98 на проекте по нише дизайна интерьеров, 3154 записи, 652 залетевших ролика.

| Статья | Стоила | Что с ней делать |
|---|---|---|
| ИИ-описания 23 роликов | $1,51 | не заказывать никогда, подпись даёт то же бесплатно |
| Instagram: посты конкурентов и комментарии | $1,03 | брать, только если они реально идут в анализ, в дашборд тем они не попадают |
| Пробный заход по 50 записей | $0,24 | сразу собирать по 100, второй заход это двойная оплата пересечений |
| Запросы, не давшие ни одного уникального залетевшего | около $0,3 | ловятся `query_report.py <папка проекта>` после сбора, при повторе не брать |
| Хвост слабых запросов | около $1,8 | 20 запросов дают 87% залетевших за $5,17, все 29 дают 100% за $7,19 |

Тот же результат собирается примерно за $5,5-6,5 вместо $9,98. Экономия не в урезании глубины выдачи,
а в отказе от лишних источников и от второго захода.

Пересечение запросов стоит около 10% сбора: один ролик приходит по нескольким формулировкам.
Подбором формулировок это не лечится. На первом проекте все пары запросов с пересечением
от десяти роликов дали в сумме $0,49 из $7,45, максимум 17 общих роликов на пару.
Единственный работающий рычаг это число запросов, а не их похожесть.
