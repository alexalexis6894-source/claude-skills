# Карта тем TikTok: анализ ниши и трендов

На входе ссылка на бренд или блогера (Instagram, TikTok, сайт). На выходе статическая страница `site/<slug>/index.html`:
все ролики ниши разбиты по темам и форматам, по каждой теме видны сумма просмотров, медиана и число роликов, любую выборку
можно открыть и смотреть подряд прямо на странице, у каждого ролика есть заголовок, описание, приём и «как снять у себя».
Страница не требует сервера: это HTML, CSS и два JS-файла.

## Что нужно заранее

| Что | Зачем | Как получить |
|---|---|---|
| Python 3.10+ | сбор, подготовка, сборка страницы | в системе, дополнительных пакетов не нужно |
| `APIFY_TOKEN` | платный сбор роликов TikTok и профиля Instagram | токен на https://console.apify.com/settings/integrations, затем `export APIFY_TOKEN=...` (Windows PowerShell: `$env:APIFY_TOKEN="..."`). Токен не класть ни в файлы проекта, ни в чат, ни в Git |
| Node 18+ и Playwright | обязательная приёмка страницы `verify.mjs` | `npm i playwright && npx playwright install chromium` (в папке проекта или глобально) |
| Баланс Apify | сбор по 30–36 запросам стоит $1–2, см. «Бюджет» | в новом аккаунте Apify есть бесплатный кредит, обычно его хватает на первый проект |

Если токена нет в окружении, сказать об этом сразу и дать ссылку выше. Токен просить только как переменную окружения, не как текст в чате.

## Интерфейс не изобретается (проверенное правило)

Два других формата результата уже пробовали и отвергли: сначала отчёт с выводами и графиками, потом карточки тем с переходом на соседнюю вкладку.
Принятый формат: человек не переходит на другие страницы, все темы идут подряд одной таблицей с показателями (сумма и медиана просмотров), таблицу можно
ранжировать, строка раскрывается шторкой и ролики из неё запускаются подряд лентой. Поэтому:

- Страницу собирает только `templates/site/` (`build_site.py` из `labeled.json` и `site.json`). Свой `app.js`, свою вёрстку, карточки тем, отдельную вкладку «Ролики», графики и текстовый отчёт вместо таблицы не писать.
- Менять интерфейс можно только в шаблоне и только по прямой просьбе пользователя, затем пересобрать страницы всех проектов. В проекте руками `site/<slug>/` не править: следующая сборка затрёт правки.
- После сборки обязательна приёмка `verify.mjs`: 44 проверки на 1280 и 390 px, нужен PASS по всем. Если красное, исправлять данные или шаблон, а не тест. Без этого прогона страницу не отдавать.

## Обязательный стандарт результата

Нельзя отдавать «отчёт с выводами и графиками» вместо карты тем. Всегда:

1. **Все ролики разбиты на темы ниши** (25–30 тем в закрытом словаре `vocab.json`, названия под нишу, а не «тема 1») и на форматы (10–13).
   Ролики не про нишу и без понятной темы уходят в «посторонние», их можно включить галочкой.
2. **Главная вкладка «Темы и ролики» – одна таблица, а не карточки и не переходы между вкладками.** Строка = тема: номер, название, число роликов, авторов, сумма просмотров,
   **медиана**, сколько от миллиона, сколько можно снять самим. Заголовки колонок сортируют (направление меняется вторым кликом), переключатель «По темам / По форматам» даёт ту же таблицу по форматам.
   Строка раскрывается шторкой на месте: внутри мини-таблица форматов этой темы (число, сумма, медиана, от миллиона; клик по формату фильтрует ролики темы),
   кнопки «▶ Смотреть подряд», «Продолжить», «Собрать в TikTok», «Ссылки», «CSV» и карточки роликов с «▶ Смотреть отсюда». Ролики запускаются лентой прямо из шторки,
   закрытие ленты возвращает к той же теме и ролику. Отдельной вкладки со списком роликов нет.
3. **Фильтры над таблицей пересчитывают все показатели**: можно ли снять, язык, география, период, порог просмотров, поиск по описанию и подписи, ранжирование роликов внутри тем
   (просмотры, лайки, сохранения, отправки и их доли от просмотров), только избранное, скрыть просмотренные, включить посторонние.
4. **Ролики открываются на самой странице**: «▶ Смотреть отсюда» запускает ленту с плеером TikTok, ролики идут подряд. Плюс ссылка в TikTok, избранное, «смотрел», копирование ссылок, CSV, сборка коллекции в TikTok.
5. **У каждого ролика** заголовок, описание, приём (хук), «как снять у себя» и отметка, можно ли снять.
6. **Вкладка «Что снимать»**: 10–16 идей, у каждой исходный ролик-референс, хук под бренд и план съёмки; сверху короткий блок выводов (`findings.html`).
7. **Вкладка «Портрет Instagram»**, если у бренда есть профиль: кто это, что продаёт, из чего лента, что собирает реакцию.
8. **Вкладка «Как считали»**: сколько собрано, как размечено, как читать медиану, расход.
9. Адрес страницы (`<slug>`) при доработке не меняется.

Шаблон интерфейса русский. Для другого языка менять надписи в `templates/site/` только по прямой просьбе пользователя; тексты разметки пишутся на языке бренда.

## Шаг 0. Папка проекта

Проект живёт в `radar/<slug>/` (slug латиницей по имени бренда, например `my-studio-tiktok`). Страница ляжет в `site/<slug>/`.
Скилл лежит в `.claude/skills/content-radar` проекта или в `~/.claude/skills/content-radar`; ниже `SKILL` – эта папка.

```bash
SKILL=.claude/skills/content-radar            # или ~/.claude/skills/content-radar
mkdir -p radar/<slug>
cp -r $SKILL/templates/example/. radar/<slug>/   # образец вымышленной студии: переписать под свой бренд
mkdir -p radar/<slug>/raw radar/<slug>/labels
echo "tmp/" > radar/<slug>/.gitignore
```

Образец `templates/example/` содержит: `vocab.json`, `LABELING.md`, `queries.json`, `site.json`, `ideas.json`, `portrait.json`, `apify/jobs-main.json`, `apify/jobs-ig.json`,
`scripts/findings.py`, `scripts/portrait.py`. Это формат файлов, а не готовые данные: **словарь, инструкцию, запросы, тексты `site.json` и идеи надо переписать под свою нишу**.
`ideas.json` из образца ссылается на ролики чужой выборки, сборка с ним упадёт, пока вы не замените `id` на ролики из своих данных.
В `site.json` поле `slug` должно совпадать с именем папки в `site/`; `day` – дата среза (ГГГГ-ММ-ДД), от неё считаются окна 30, 90 и 180 дней.

Команды конвейера (все пути от корня проекта):

```bash
python3 $SKILL/templates/apify/apify_jobs.py radar/<slug>/apify/jobs-main.json --max-usd 2 --threads 8   # сбор (шаг 4)
python3 $SKILL/templates/pipeline/prepare.py radar/<slug>              # raw/*.json.gz -> all.json
python3 $SKILL/templates/pipeline/shard.py radar/<slug> 1000 130 "-ru-|-loc-"   # all.json -> shards/
python3 $SKILL/templates/pipeline/merge.py radar/<slug>                # labels/ -> labeled.json
python3 $SKILL/templates/site/build_site.py radar/<slug> --root=site   # -> site/<slug>/
node $SKILL/templates/site/verify.mjs <slug> --root=site               # приёмка
```

## Шаг 1. Изучить автора и нишу

Прочитать всё, что дал пользователь: ссылки на профили, переписку, прошлые материалы. Открывать страницы без спроса. Из этого вытащить и записать своими словами:

- ниша и что человек продаёт, чем зарабатывает;
- какой материал у него уже есть (объекты, продукты, съёмки, документы, клиенты);
- чего у него нет (времени, команды, разрешений, доказанных кейсов);
- на какую площадку он публикует и на какую аудиторию.

Это основа `LABELING.md`. Точность здесь важнее всего: от определений `fit` зависит, какие темы страница назовёт снимаемыми.

## Шаг 2. Спросить недостающее

Один заход вопросов, не больше четырёх. Спрашивать только то, чего нет в материалах.

| Вопрос | Зачем |
|---|---|
| Что автор точно не будет снимать | половина ниши обычно закрыта, без этого отбор врёт |
| Цель: охват, заявки или продажа услуги | меняет, какие темы считать сильными |
| Площадка: TikTok, Reels или обе | TikTok дешевле и даёт поиск, Instagram нужен для портрета бренда |
| Потолок бюджета на сбор | смета считается до запуска, деньги живые |

Если человек не отвечает на что-то, взять умолчание и сказать, какое: TikTok, 30–36 запросов, потолок $2, порог залетевшего 500 тыс. просмотров.

## Шаг 3. Словарь ниши, инструкция разметчику и запросы

В `radar/<slug>/` три файла, образец – `templates/example/`:

- `vocab.json`: оси `theme` (25–30 значений с названиями под нишу, плюс «Не про <нишу>» и «Неясно»), `format` (10–13), `fit` (`yes`, `part`, `no`), `conf` (`hi`, `lo`), `lang`.
  Значения взаимоисключающие и понятные без пояснений. Если у бренда есть своё оборудование, метод или продукт, это отдельная тема или прямая подсказка.
- `LABELING.md`: кто бренд, что у него есть для съёмки, поля строки (`id, theme, format, fit, conf, lang, title, description, hook, idea`), подсказки по темам,
  определения `yes`, `part`, `no` под этого автора, правила `conf` и запрет выдумывать содержание видео сверх подписи.
- `queries.json`: 30–40 запросов словами зрителя, не профессиональными терминами: предметные области ниши, этапы, деньги, ошибки, стили, местные запросы
  (город, район), англоязычный сегмент той же темы. Раскладывать по дорожкам (`ru`, `loc`, `en`, `life`): `[{"i": 1, "track": "ru", "q": "..."}]`. Дорожка попадает в имя прогона.

## Шаг 3.5. Бюджет: как не переплатить

Фактический счёт первого проекта $9,98 за 3154 записи и 652 залетевших ролика. Тот же результат собирается за $5,5–6,5. Правила, из которых это следует:

- **Один заход, сразу по 100 записей на запрос.** Пробный сбор по 50 с последующим добором это двойная
  оплата пересечений. Резать глубину ради экономии бессмысленно: доля залетевших в хвосте выдачи
  выше, чем в начале (35% на позициях 76–100 против 23% на 1–25). Для другой ниши это надо проверять `query_report.py`, закон не универсален.
- **Дешёвая разведка запросов не работает.** Качество запроса по первым двадцати записям совпадает
  с качеством по сотне только на 0,66 по рангам: сильные запросы выглядят пустыми, потому что наверху
  свежие ролики без просмотров. Пробой по 20 записей отсеивать омонимы и чужие жанры, а не выбирать лучшие слова.
- **Instagram брать, только если он идёт в анализ.** В таблицу тем посты конкретных аккаунтов не входят,
  это отдельная выборка (вкладка «Портрет»). Профиль бренда стоит копейки, посты конкурентов и комментарии дороги.
- **ИИ-описания и транскрипции не заказывать.** $1,51 за 23 ролика, подпись даёт то же бесплатно. Раннер сам отказывается запускать такие опции.
- **25–29 запросов хватает.** Двадцать лучших дают 87% залетевших, двадцать пять дают 96%.
  Пересечения съедают около 10% сбора и подбором формулировок не лечатся: рычаг только один, число запросов.

После сбора посчитать отдачу, чтобы следующий сбор по этой нише стоил меньше (денег не тратит, читает `raw/`):

```bash
python3 $SKILL/templates/query_report.py radar/<slug>          # порог 500 тыс.; вторым аргументом свой порог
```

Отчёт показывает цену за находку по каждому запросу, распределение по глубине выдачи, минимальный набор запросов и запросы, не давшие ничего уникального.

## Шаг 4. Смета и запуск сбора

Цена записи TikTok у `apidojo~tiktok-scraper` около $0,0003 (120 записей на запрос, $0,02–0,04). Считать: запросов × режимов × $0,035. Потолок каждого
прогона `max_usd` 0,04, сумма потолков не больше потолка запуска `--max-usd`. Без отдельного согласия пользователя не больше $2. Платные ИИ-описания и транскрипты нельзя.
Перед первым запуском открыть `references/actor-playbook.md`: режимы выдачи (`RELEVANCE` + полгода первым), реестр акторов, цены. Цены проверять заново, акторы их меняют.
Показать пользователю смету (число прогонов × потолок) и запустить после его согласия.

Файл заданий (образец `templates/example/apify/jobs-main.json`): на каждое слово прогон `RELEVANCE` + `LAST_SIX_MONTHS`, на главные слова ещё
`MOST_LIKED`. Имя прогона только латиницей и с номером (`tt-q07-ru-fresh`): кириллица в имени даёт одинаковые файлы. Часть имени `-ru-` и `-loc-` помечает
русские и местные запросы: `shard.py` берёт их ролики даже с малыми просмотрами. Файл заданий удобно сгенерировать маленьким скриптом из `queries.json`.
Поле `out` в файле заданий (`raw`, для Instagram `ig`) считается от папки проекта, то есть от родителя папки `apify/`.

```bash
export APIFY_TOKEN=...      # один раз в этой сессии терминала
python3 $SKILL/templates/apify/apify_jobs.py radar/<slug>/apify/jobs-main.json --max-usd 2 --threads 8
```

Раннер печатает лимит аккаунта до и после запуска, пишет `radar/<slug>/raw/<имя>.json.gz` и строку расхода в `radar/<slug>/apify/spend.jsonl`. Готовые прогоны
он пропускает, поэтому оборвавшийся или частично упавший сбор просто запускают ещё раз. Если не запустилась часть заданий, сбор не считать законченным.
Профиль Instagram бренда для вкладки «Портрет»: те же команды с `apify/jobs-ig.json` (`apify~instagram-profile-scraper` и `apify~instagram-post-scraper`, около $0,03 за 23 поста).
Остаток баланса и расход смотреть в консоли Apify (Billing): счётчик в ответе API отстаёт на минуты, итог сверять после завершения.

## Шаг 5. Короткая проверка сбора

```bash
python3 $SKILL/templates/pipeline/prepare.py radar/<slug>
```

`prepare.py` даёт `all.json`: уникальные ролики. Посмотреть медиану, долю русских, число роликов с датой; выбрать порог в `site.json -> default_threshold`
так, чтобы выше него лежало 15–30% выборки (а не брать 500 тысяч из чужой ниши). Окно выдачи полгода: фильтры периода на странице 30, 90 и 180 дней.

## Шаг 6. Разметка: каждый ролик, не итог

Сначала написать `vocab.json` и `LABELING.md` под нишу: оси `theme`, `format`, `fit`, `conf`, `lang`; поля текстом `title` (3–7 слов), `description` (одно предложение),
`hook` (приём), `idea` (одно предложение, как снять у себя, только при fit yes и part). Правила fit пишутся под бренд: что у него есть из оборудования, людей и мест.
Если у бренда есть своё оборудование или метод, это отдельная тема или явная подсказка в `LABELING.md` (в первом проекте это упустили: фирменное оборудование агенты сначала сочли чужим).

```bash
python3 $SKILL/templates/pipeline/shard.py radar/<slug> 1000 130 "-ru-|-loc-"     # мин. просмотров, размер шарда, регулярка прогонов «брать всегда»
```

По одному агенту на шард (в Claude Code – параллельные субагенты, модель средняя, например Sonnet, с высоким усилием). Больше 20 одновременно обычно не нужно: запустить 20,
остальные по мере освобождения. Если субагентов нет, шарды размечаются подряд в основной сессии (дольше, но результат тот же).
Промпт агента: прочитать `LABELING.md` и `vocab.json`, прочитать шард `shards/shard-NN.json`, записать `labels/shard-NN.jsonl` (одна строка на ролик, тот же порядок, `id` строкой),
проверить командой, вспомогательные скрипты класть в `radar/<slug>/tmp/` (папка в .gitignore), в ответ вернуть число строк, топ-5 тем, число fit=yes и conf=lo. Один шард идёт 3–4 минуты.

## Шаг 7. Свести и проверить

```bash
python3 $SKILL/templates/pipeline/merge.py radar/<slug>
```

Скрипт валит расхождения id, значения вне словаря и пустые заголовки. Потом прочитать глазами топ роликов по каждой крупной теме и спросить себя: я бы это
посоветовал автору? Если у бренда есть своё оборудование или метод, проверить, что эти ролики не ушли в `fit: no`, и при необходимости исправить правилом
в `labeled.json` до сборки (небольшой скрипт `radar/<slug>/scripts/fixes.py`, чтобы правка повторялась при пересборке). Темы с малой выборкой (меньше 8–10 роликов) не выдавать за вывод.

## Шаг 8. Идеи, портрет, выводы, сборка страницы

- `ideas.json`: 10–16 карточек `{id, theme, title, hook, plan, mechanic}`, где `id` – ролик-референс из выборки (сборка валится, если id нет). Формат см. в образце.
- `portrait.html` (вкладка «Портрет Instagram», нужна, если есть профиль): положить выгрузки в `radar/<slug>/ig/` (`ig-profile.json.gz`, `ig-posts.json.gz` – их даёт `jobs-ig.json`),
  заполнить `radar/<slug>/portrait.json` (поля `note`, `who`, `sells`, `rubrics`, `points`, `extra`, образец рядом) и запустить
  `python3 $SKILL/templates/example/scripts/portrait.py radar/<slug>`. Таблицы рубрик и лучших постов считаются из данных, тексты «Кто это», «Что продаёт» и выводы пишутся по сайту и профилю бренда.
  Без профиля файл не нужен, вкладка тогда не создаётся. Формат без скрипта: HTML-фрагмент с заголовками `<h3>` (Кто это, Что продаёт, Из чего состоит лента, Что собирает реакцию),
  таблицами в `<div class="tablewrap"><table>` и ячейками чисел с классом `num`.
- `findings.html`: 4–6 коротких выводов с числами из данных, лежит над идеями. Заготовка: `python3 $SKILL/templates/example/scripts/findings.py radar/<slug> [мин. роликов в теме]`
  (темы по сохранениям, охват снимаемого, форматы, язык и география). Прочитать результат и дописать смысл под бренд; числа берутся из `labeled.json`, не из головы.
  Формат: `<h3>Что показали данные</h3><ul><li><b>Вывод.</b> объяснение с числом</li>...</ul><p class='small'>оговорка</p>`.
- `site.json`: бренд, тексты, палитра, фильтры; образец `templates/example/site.json`. Поля: `slug`, `day`, `day_ru`, `key` (префикс ключей localStorage), `title`, `description`,
  `brand_upper`, `meta_line`, `eyebrow`, `h1`, `lead`, `nav_ideas`, `fit_names`, `fit_short`, `fit_opts`, `langs`, `periods`, `thresholds`, `default_threshold`, `local` (необязательный фильтр географии по регулярке),
  `search_placeholder`, `collection_example`, `ideas_title`, `ideas_note`, `idea_hook_label`, `portrait_title`, `footer_brand`, `footer_html` (необязательно: подпись, ссылки на бренд, контакты;
  без поля подвал остаётся с одним названием), `method_fit_note`, `noise_themes`, `merge` (слияние тем при сборке), `theme` (цвета). Поле `out` необязательно: полный путь папки страницы вместо `<root>/<slug>`.

```bash
python3 $SKILL/templates/site/build_site.py radar/<slug> --root=site      # корень выдачи по умолчанию site
```

Сборка проверяет стандарт сама: не меньше 12 тем и 5 форматов, заголовок и описание у 95% роликов, не меньше 10 идей. Результат: `site/<slug>/` с четырьмя файлами
(`index.html`, `data.js`, `app.js`, `style.css`). Размер `data.js` растёт с выборкой: две-три тысячи роликов дают 2–3 МБ, это нормально.

## Шаг 9. Приёмка

```bash
node $SKILL/templates/site/verify.mjs <slug> --root=site
```

Скрипт сам поднимает локальный сервер, проходит страницу на 1280 и 390 px и печатает PASS/FAIL по каждому из 44 пунктов: таблица тем строками, сортировка колонок,
шторка с форматами и роликами, лента из шторки и возврат на то же место, разрез по форматам, фильтры, идеи, метод, полнота разметки, отсутствие длинного тире U+2014, отсутствие ошибок JS.
Плеер TikTok проверка не загружает (запросы к tiktok.com блокируются), она убеждается, что iframe ленты и кнопки на месте. Нужен PASS по всем пунктам.
Если нет Playwright, скрипт скажет, что поставить. Если браузер лежит в нестандартном месте, задать `CHROMIUM_PATH=/путь/к/chrome`.
Дополнительно открыть страницу в браузере и просмотреть таблицу, шторку и ленту глазами, в том числе на узком экране.

## Шаг 10. Публикация

Папка `site/<slug>/` статическая, подойдёт любой хостинг файлов. Три простых варианта:

1. **Локально, без публикации.** `python3 -m http.server 8000 -d site`, затем открыть http://localhost:8000/<slug>/. Открывать `index.html` двойным кликом тоже можно,
   но через сервер надёжнее (плеер TikTok требует обычного http-адреса).
2. **GitHub Pages.** Закоммитить `site/` в репозиторий и в Settings → Pages выбрать Source: «GitHub Actions» или ветку с папкой; проще положить содержимое `site/` в ветку `gh-pages` или в папку `docs/`
   (тогда адрес `https://<имя>.github.io/<репозиторий>/<slug>/`). Для приватного репозитория Pages доступны не на всех тарифах.
3. **Netlify Drop.** Открыть https://app.netlify.com/drop и перетащить папку `site` целиком: сайт получит адрес вида `https://<случайное-имя>.netlify.app/<slug>/`, регистрация по запросу.

Адрес открывает любой, кто знает ссылку; в странице стоит `noindex`, поисковики её не индексируют. На странице лежат подписи и ссылки на публичные ролики TikTok и разбор бренда: прежде чем отправить ссылку клиенту
или выложить публично, убедиться, что в `ideas.json`, `portrait.html` и `site.json` нет того, что показывать нельзя.
После публикации повторить приёмку по живому адресу (в `--base` корень сайта, страница лежит по `<base>/<slug>/`):

```bash
node $SKILL/templates/site/verify.mjs <slug> --base=https://<адрес-сайта>
```

Пользователю дать короткую выжимку и ссылку.

Справка по акторам, ценам и полям: `references/apify-notes.md`, `references/actor-playbook.md`.

## Правила, которые не обсуждаются

- Результат всегда таблица тем со шторками по стандарту выше, только из шаблона `templates/site/`; приёмка `verify.mjs` обязательна. Не писать длинный отчёт с графиками вместо неё.
- Все ролики размечены по темам ниши; без разбивки по темам результат не сдаётся.
- Платные ИИ-описания и транскрипции Apify не заказывать. Смысл вытягивается из подписи бесплатно.
- Apify только с потолком: `max_usd` на каждый прогон и `--max-usd` на запуск, без отдельного согласия пользователя не больше $2. Токен только в переменной окружения.
  Instagram бренда сначала бесплатно (`/embed/` даёт 6 последних постов), полный профиль через Apify дешёвый.
- Есть дешёвый тест, способный открыть более выгодный путь, значит тест проводится обязательно (см. actor-playbook).
- В текстах страницы запрещено длинное тире U+2014; дефисы и «–» в диапазонах допустимы. Перед публикацией поиск U+2014 по `site/<slug>/` даёт ноль (приёмка это проверяет).
- Страница честно говорит, чего данные не доказывают: причину охвата, содержание видео (разметка по подписи), перенос между площадками и странами, число заявок.
