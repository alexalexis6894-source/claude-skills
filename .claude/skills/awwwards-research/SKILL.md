# Awwwards: исследование по элементам

Цель: получить разнообразный набор применимых дизайн-приёмов с источниками. Число просмотренных сайтов само по себе не является результатом.

Применять перед исследовательской фазой design-consultation. Перед design-shotgun использовать уже собранный пакет, без повторного обхода источников. Этот скилл дополняет оба процесса, не запускает генерацию макетов, публикацию или расход платных внешних сервисов сам по себе.

## Порядок работы

1. Из контекста определить аудиторию, целевое действие, позиционирование, доступные фото/видео, ограничения мобильной версии. Недостающие необязательные данные обозначить как предположения.
2. Прочитать [протокол](references/protocol.md). Выбрать бюджет; пользовательский потолок имеет приоритет. Считать весь расход исследования, включая вход, выход, повторный контекст, изображения и агентов. Не выдавать оценку за измерение.
3. Определить подходящую выборку аналогов. Внутри неё первичны награды и рейтинги Awwwards, затем применимость и разнообразие. Извлекать названия, URL, награды, даты, описание, теги и ссылки. Не открывать внешние сайты на этапе первичного отбора.
4. Отделять факты карточки от собственной интерпретации. Номинация не равна награде; коллекция пользователя не подтверждает награду; описание не доказывает удобство или рост конверсии. Авторство пояснения указывать только при наличии атрибуции.
5. Со ВСЕХ сайтов выбранной выборки собрать ВСЕ собственные Elements, включая Desktop и Mobile. Удалять только дубли ссылок. Сохранить название, описание если есть, теги, медиа и родителя. Отбор для визуального просмотра делать после полного сбора. Итоговый балл, оценки жюри и среднее загруженных пользовательских голосов хранить раздельно.
6. Внешний сайт открывать только для конкретного вопроса, который нельзя разрешить материалами Awwwards. Сформулировать вопрос до перехода. Не читать весь код, DOM, страницы и состояния по умолчанию.
7. Передать design-consultation краткую карту приёмов, ограничения и рекомендации для DESIGN.md. Передать design-shotgun только выбранные источники и 2-3 разные концепции, если пользователь не задал другое число. У каждой концепции свои композиция, типографика и визуальный характер.

## Обязательный результат

- Каталог коротких карточек с URL и статусом проверки, сохранённый вне контекста модели.
- Пакет для дизайна: 12-15 приёмов или меньше, если покрытие уже достаточное; для каждого применение, источник, уверенность и необходимые материалы.
- Отчёт бюджета: измеренный расход либо явно обозначенная оценка; число найденных, разобранных, визуально проверенных и посещённых внешних сайтов считать отдельно.
- Причина остановки: достаточное покрытие, исчерпан бюджет или недоступны источники.

Не превращать банк референсов в копию чужого сайта. Извлекать принципы и связывать их с задачами данного продукта. Не придумывать шрифты, анимации, награды и бизнес-результаты по одной миниатюре.

## Сборщик (локальный запуск)

Сбор идёт прямо с вашей машины, без внешних сервисов и облачных задач. Нужны Node.js 18+ (`fetch` встроен) и
Python 3 с `beautifulsoup4` (`pip install beautifulsoup4`). Из корня проекта:

```sh
# 1. манифест: JSON-массив объектов с полем url (карточки https://www.awwwards.com/sites/<slug>)
echo '[{"url":"https://www.awwwards.com/sites/example-site"}]' > sites-manifest.json
# 2. скачать карточки (пауза 250 мс между запросами, кэш в папке raw)
node .claude/skills/awwwards-research/scripts/collect.mjs sites-manifest.json raw
# 3. извлечь проекты и ссылки на их Elements
python3 .claude/skills/awwwards-research/scripts/extract.py raw catalog.json
# 4. из catalog.json собрать манифест всех elements (https://www.awwwards.com/inspiration/<slug>),
#    скачать тем же сборщиком в новую папку и повторить извлечение
```

Правила сбора: сборщик принимает только адреса `https://www.awwwards.com/sites/…` и `/inspiration/…`;
при ответе 429 останавливается (сайт ограничивает частоту запросов, большие списки делить на 4–7 частей и
идти с паузами между запусками); уже скачанные карточки берёт из кэша, поэтому для свежего исследования
использовать новую папку. Проверить обратные ссылки элементов на проекты. Динамические голоса сообщества
у победителей требуют отдельной браузерной проверки. Условия использования Awwwards соблюдать:
собирать только публичные карточки в разумном объёме для собственного исследования.
