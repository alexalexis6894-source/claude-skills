# Слияние правил: дополнение, а не замена

Свой CLAUDE.md человека главнее правил набора. Цель: после слияния в файле есть всё полезное
из набора, чего там не было, и ни одного правила, которое повторяет или спорит с уже написанным.

Файлы:
- **Его правила:** `~/.claude/CLAUDE.md` (или `./CLAUDE.md` при установке в проект).
- **Эталон набора:** `~/.claude/skills-kit/RULES.md` (или `./.claude/skills-kit/RULES.md`).
- **Блок набора** внутри его файла: между `<!-- skills-kit:begin -->` и `<!-- skills-kit:end -->`.
  Только этот блок принадлежит набору. Текст вне блока не менять ни на символ.

Если файла нет или вне блока пусто: записать эталон в блок целиком, слияние не нужно, шаги 2–4 пропустить.

## 1. Прочитать оба текста целиком

Прочитать весь CLAUDE.md человека (и файлы, которые он подключает через `@путь`, если они есть)
и весь эталон. Прежний блок набора при сравнении не считать «его правилами»: блок пересобирается заново.

## 2. Разобрать эталон на отдельные правила и сверить каждое

Каждый пункт эталона (одна мысль = одно правило) отнести к одному классу:

| Класс | Признак | Что делать |
|---|---|---|
| Уже есть | у человека сказано то же самое, хотя бы другими словами | не добавлять |
| Частично есть | у человека есть общая мысль, у нас конкретика сверх неё | добавить только недостающую конкретику, одной строкой |
| Противоречит | у человека прямо иначе (другой формат, язык, модель, порядок git) | не добавлять, его правило главнее |
| Новое | у человека об этом ничего нет | добавить |

Сравнивать по смыслу, а не по словам: «проверяй результат в браузере» и «перед сдачей открой
страницу и посмотри скриншоты» – одно правило. Сомнение «есть или нет» решать в пользу «уже есть»:
лишний повтор хуже пропуска мелочи.

## 3. Записать блок

Сделать копию `CLAUDE.md.bak`. Заменить блок набора (или дописать его в конец файла, если блока нет):

```
<!-- skills-kit:begin -->
# Дополнение из набора skills-kit
Правила выше в этом файле главнее; здесь только то, чего в них не было.

<только классы «Новое» и недостающая часть «Частично есть», сгруппированные по разделам эталона>
<!-- skills-kit:end -->
```

Формулировки брать из эталона и не дописывать своего. Сжимать можно слова, но не смысл:
каждое правило эталона, которое не «уже есть» и не «противоречит», попадает в блок целиком,
со всеми оговорками и исключениями (например «мелкие правки без разведки»). Частые потери при
сжатии: исключения, требования к тону, запреты вида «X не заменяет Y», «на сколько хватит».

## 4. Независимая сверка отдельным субагентом (обязательно)

Запустить одного субагента (Claude Code: `model: sonnet`, `effort: high`; в других средах –
доступная сильная модель). Ему не сообщать свою разметку и выводы, только тексты и задачу:

> Даны три текста: A – правила человека (файл без блока skills-kit), B – новый блок skills-kit,
> C – эталон правил набора. Проверь:
> 1. Для каждого пункта B: повторяет ли он по смыслу что-то из A (процитируй место в A)
>    или противоречит A (процитируй). Ответ по пунктам: «новое / повтор / противоречие».
> 2. Какие правила из C не покрыты ни A, ни B и при этом не противоречат A (пропуски).
> 3. Изменён ли текст вне блока по сравнению с исходником (дать diff или «не изменён»).
> Верни таблицу и короткий итог. Ничего не исправляй сам.

Для пункта 3 передать субагенту исходник из `.bak`.

По ответу: убрать из блока повторы и противоречия, добавить пропуски. Если правок было больше
двух, запустить сверку ещё раз (не больше двух раундов). Если субагент и ведущий расходятся
в оценке пункта, решать в пользу «не добавлять».

## 5. Отчёт человеку

Коротко и по группам:
- ✅ добавлено: N правил (перечислить заголовками);
- ⏭️ уже было у вас: N (перечислить);
- ⚖️ ваше правило главнее, наше не добавлено: N (что именно);
- 🔍 результат сверки субагентом: повторов 0, противоречий 0, текст вне блока не изменён;
- где копия прежнего файла (`.bak`).

При обновлении набора (новый RULES.md) повторить те же шаги: блок пересобирается с нуля.
